# Watch recorder: build, install, and FIT format

Simple Connect IQ watch app for Instinct 3 AMOLED 45 mm and 50 mm.
Records accelerometry through Garmin SensorLogger and captures BBI when Garmin
delivers it. No sleep scoring, staging, GPS, network upload, or raw PPG recording.

## Review status (v1.1.1 source)

The START crash reported on the 45 mm watch was reproduced in the simulator.
v1.1 exceeded the runtime developer-field count limit: it tried to create 34 FIT
fields, and failed at the 17th. v1.1.1 uses 11 total fields (7 RECORD, 4 SESSION),
packing metadata into arrays. It also checks the count before allocating a field.

Both supported device profiles have previously built successfully. Public releases
currently distribute source only. Build your own PRG in `bin/v1.1.1/` before
following the installation steps below. Run commands from the repository root.

Fixed in the source:

- Check Garmin's Boolean start, stop, and save results. A failed save keeps the
  session in memory for retry, blocks a new recording, and prevents normal BACK
  navigation from exiting the app. OS termination or power loss can still lose data.
- Save partial recordings on callback errors; field errors do not prevent an
  attempt to save the native accelerometer recording.
- Retain elapsed time and logged sample counts after saving.
- Explicitly request the heart-rate sensor, and show waiting, absent, or stale BBI.
- Add bounded, sequence-numbered BBI history and a final SESSION snapshot.
- Separate actual FIT accelerometer count from callback diagnostics.
- MENU no longer stops a recording. UP/DOWN/MENU refresh the display on demand.
  No periodic display-update timer or backlight forcing is used.

Validation on 2026-09-12: all 6 Monkey C tests pass on both device profiles,
including actual session start/stop/save, ready/error-screen drawing, buffer
behavior, and simulated save/stop failures. All 12 Python decoder tests pass;
the June legacy FIT also parses and is correctly identified as legacy.
This historical test run did not establish physical BBI availability, exported
FIT interoperability, display timeout, or overnight battery/storage behavior.
These properties require device-specific checks; later exploratory recordings
do not establish general compatibility or physiological validity.

## Build the update

Open this project in VS Code and use its ordinary PowerShell terminal:

```powershell
.\scripts\build.ps1
```

This builds both supported sizes using the SDK selected by SDK Manager (or
`GARMIN_SDK_HOME`) and your `GARMIN_DEVELOPER_KEY` signing key. The script also
accepts `-SdkPath` and `-KeyPath`; its local fallback key location is
`$env:USERPROFILE/Downloads/developer_key`. It publishes a PRG to `bin/v1.1.1/`
only after that model's compiler invocation succeeds. It does not install anything
on the watch. Do not substitute a different signing key or change the app ID.

To build just one size:

```powershell
.\scripts\build.ps1 -Device instinct3amoled45mm
```

The script accepts `-SdkPath` and `-KeyPath` if your local paths have changed.
Alternatively, run **Monkey C: Build for Device** from the VS Code command palette,
select your exact Instinct 3 AMOLED model and the existing key, and choose an output
under `bin/v1.1.1/`. Wait for **BUILD SUCCESSFUL**. If building fails, do not install
an old PRG as though it were the new build; retain the compiler output for review.

## Update or reinstall on the watch

1. Stop/save any current recording and exit the watch app.
2. Connect the watch to the PC using a USB data cable. In File Explorer open the
   Garmin device, then its internal storage if shown, then `GARMIN/APPS`.
3. Back up the existing app PRG and any FIT recordings you want to keep to your PC.
4. Copy ONLY the newly built PRG matching your watch size from `bin/v1.1.1/` into
   `GARMIN/APPS`. Use the SAME filename as your previous sideload, for example
   `OvernightAccelBbi.prg`, and replace that app's file. Do not copy both sizes,
   debug XML, JSON, or the entire bin folder. Do not delete unrelated Garmin files.
5. Disconnect cleanly once copying has finished. Reopen the app on the watch and
   verify the screen title is **Overnight v1.1.1**. Restart the watch if it still
   shows the old app after a completed copy.
6. If you previously removed the app, the same copy procedure reinstalls it. If
   an old app uses an unfamiliar autogenerated filename, do not guess which PRG
   to overwrite: remove only this app through the watch's app management first,
   then sideload the new file under a consistent name. Back up data first.

Official Garmin sideload reference:
https://developer.garmin.com/downloads/connect-iq/wearable-programming-for-the-active-lifestyle.pdf
(Run an App on a Real Device). Modern VS Code replaces the older IDE shown there.

## Five-minute test

1. Charge the watch, verify available storage, wear it normally, and launch v1.1.1.
2. Press START to record. The status should become **Recording**.
3. After 30-60 seconds, press UP or DOWN to refresh. **FIT accel** and **Callbacks**
   should increase. If BBI is delivered, **BBI received** should increase too.
   **No BBI received** is a failed BBI-acquisition test even if ordinary HR exists.
4. Record about five minutes. Include a short wrist movement between quiet periods.
   Leave the display untouched for part of the test to check its timeout.
5. Press START again to stop/save. **Saved** means Garmin returned success.
   **Saved partial** means a recording was saved with a capture/field warning.
   **Save failed** or **Stop failed** means press START to retry and do not exit.
6. Press BACK after the saved result to exit. During recording, BACK instead
   stops/saves and stays on the result screen; MENU only refreshes.
7. Reconnect USB and COPY the newest matching FIT from `GARMIN/ACTIVITY` into a
   new folder under `offline_processing/data/`. Preserve the watch original.
8. Check the FIT for accelerometer messages and BBI sequence coverage before an
   overnight trial. A zero-BBI result needs investigation on the actual firmware;
   API support does not guarantee the optical sensor supplies BBI during an activity.

The PC is not needed while recording. Normal activity recording may affect other
Garmin overnight features; simultaneous native sleep tracking is not established.
The app does not force the display off. Disable activity Always On Display and
adjust timeout/gesture settings on the watch as desired; menu labels vary by firmware.
UI counters are intentionally snapshots: use UP/DOWN/MENU to refresh.

## FIT format and limitations

Native `accelerometer_data` messages are written by SensorLogger. Its API exposes
no sample-rate option. The 25 Hz request in the source belongs only to the callback
used for diagnostics. The earlier physical FIT contained approximately 100 Hz
native samples. Measure each new FIT's timestamps; do not assume either rate or
acceleration scaling from the callback setting or parser unit label alone.

Scalar fields `bbi_count` (ID 0), `bbi_latest` (1), `accel_samples` (10), and
`bbi_total` (11) remain for inspection. The old eight `bbi_1`..`bbi_8` fields
are no longer written. Use the history decoder for the interval sequence.
`accel_samples` counts callback samples, not the native FIT samples.

Schema 3 adds these compact RECORD fields:

| ID | Field | Meaning |
| --- | --- | --- |
| 13 | bbi_history | 24 UINT16 interval slots, milliseconds |
| 14 | bbi_rx_ms | 24 UINT32 callback-arrival offsets, milliseconds |
| 24 | logger_meta | Eight UINT32 metadata values, in the order below |

Metadata array order:
0. Schema version (3).
1. History count: min(bbi_total, 24).
2. All sensor callbacks received.
3. Callbacks containing no intervals.
4. Delivered values outside 1..65534 ms.
5. Native SensorLogger sample count.
6. Monotonic elapsed recording time in milliseconds.
7. UTC start anchor in Unix seconds.

For one-based interval sequence `s`, the physical slot is `(s - 1) % 24`.
Each snapshot covers sequences `bbi_total - history_count + 1` to `bbi_total`.
The final SESSION uses `final_bbi_history` (40), `final_bbi_rx_ms` (41),
`final_bbi_total` (42), and `final_logger_meta` (51), with the same metadata layout.
This preserves the final buffer without waiting for another RECORD message.
The payload is 187 RECORD bytes and 180 SESSION bytes. Both byte budgets and the
11-field allocation have passed the simulator's actual session test.

Snapshots reduce overwrite losses but do NOT guarantee losslessness. A gap longer
than 24 delivered intervals can exceed the retained history. Sequence gaps reveal
intervals the app received but the FIT did not preserve. They cannot reveal beats
the sensor never delivered. An empty callback is not proof of a sensor dropout.
The developer-field record payload is about 5 MB per eight hours at one record per second,
in addition to native accelerometry. Overnight storage/battery use must be measured.

Arrival timestamps are NOT beat timestamps. All intervals in one callback share
an arrival offset. The UTC anchor has one-second resolution; callback latency is
unknown. Do not interpolate through missing sequences or infer subsecond alignment
with acceleration from arrival times alone. Invalid/unrepresentable interval values
are counted and stored as zero, not silently treated as physiological measurements.

Official API references:
- https://developer.garmin.com/connect-iq/api-docs/Toybox/FitContributor/Field.html
- https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityRecording/Session.html
- https://developer.garmin.com/connect-iq/api-docs/Toybox/SensorLogging/SensorLogger.html
- https://developer.garmin.com/connect-iq/api-docs/Toybox/Sensor/HeartRateData.html

## Read new BBI snapshots

To inspect numbered interval history, install the analysis dependencies:

```powershell
python -m pip install -r offline_processing/requirements.txt
python offline_processing/fit_bbi.py PATH_TO_NEW_FIT
```

From a notebook launched in `offline_processing`:

```python
from fit_bbi import load_bbi
rows, report = load_bbi(FIT_PATH)
interval_df = pd.DataFrame(rows)
print(report)
```

Inspect `missing_sequence_ranges`, `invalid_recovered_intervals`, and
`final_summary_present`. A complete received sequence is not proof of physiological
BBI validity. Identical interval values are never deduplicated by value, only by
their sequence number. Legacy FIT files are explicitly identified, not reinterpreted
as numbered snapshots. The decoder supports both older schema 2 snapshots and
compact schema 3. Do not concatenate snapshots from multiple sessions.

## Regression tests

```powershell
python -m unittest discover -s offline_processing -p test_fit_bbi.py -v
.\scripts\build.ps1 -Tests -Device instinct3amoled45mm
```

For Monkey C tests, set `GARMIN_SDK_HOME` to your SDK directory, start the
Connect IQ simulator normally, then run:

```powershell
& (Join-Path $env:GARMIN_SDK_HOME 'bin\monkeydo.bat') bin\tests\OvernightAccelBbi-instinct3amoled45mm.prg instinct3amoled45mm /t
```

Repeat for 50 mm when needed. Unit tests are excluded from normal device builds.
Check the PASSED/FAILED summary; monkeydo can return exit code 0 even when tests fail.
The simulator smoke test creates/saves a real simulator FIT session; it cannot
establish physical optical BBI availability or overnight power behavior.
